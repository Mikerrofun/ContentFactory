# LESSONS — канонические правила, выведенные из правок Романа

Этот файл содержит правила, которые применяются ко всем генерируемым постам.
Обновляется ВРУЧНУЮ Романом после дистилляции наблюдений из `lessons_pending/`.

---

## L1. Каждый пост — самодостаточный

Каждый пост (включая посты внутри серии) должен:
- Читаться отдельно, без знания о предыдущих постах
- Если контекст из предыдущего поста нужен — даём его одной короткой фразой внутри
- НЕ начинаем посты с "Продолжаю серию", "В прошлом посте" — это не основа

Если уместно — можно сослаться на предыдущий пост одной фразой ("я уже как-то рассказывал про..."), но это **приём**, а не **структура**.

---

## L2. У каждого поста — заголовок

Первой строкой каждого поста — короткий заголовок (одна строка, до 60 символов).
Заголовок может быть жирным (`**...**`) или просто первой строкой — на усмотрение редактора, но он должен **визуально отделяться** от тела.

После заголовка — пустая строка, затем хук и тело.

Заголовок:
- Цепляет (как заголовок поста в блоге, а не описание оглавления)
- Не повторяет тему задания дословно
- Может быть провокацией, цифрой, вопросом, обещанием

---

## L3. CTA не обязателен

По умолчанию пост может заканчиваться без CTA. Если CTA есть — он один, мягкий ("если откликается — поставьте реакцию"), без давления.

---

## L4. AI-маркеры — чего не делать

Следующие конструкции — признаки AI-текста. Не использовать:

- **"Скажу как есть"** — это фраза из устной речи Романа на вебинарах, не из его блога. В письменных постах не использовать.
- **"Понимаете разницу/к чему я веду/в чём фокус?"** — повторяющийся риторический ход. Максимум один раз на пост, и только если естественно.
- **Em-dash (—) в избытке** — Роман в BEST.md использует обычные тире и точки. Em-dash разрешён только там, где он несёт смысловую нагрузку (вставная конструкция).
- **Bold (`**текст**`) для эмфазы внутри тела поста** — Роман использует bold только в заголовках. Внутри поста — не выделять.
- **Rule of three везде** — не строить каждую мысль через "А, Б, В". Если уж надо — варьировать с двойными и одиночными.
- **Negative parallelism "Не X. А Y" подряд** — приём ок, но не штамповать.
- **"Я серьёзно" / "Я не шучу"** — AI-эмфаза.
- **"А по факту..." / "На самом деле..."** в одном посте больше двух раз — AI-контрастная конструкция.
- **Афоризмы в концовку** ("Каждому своё", "Тут выигрывает спокойный") — звучит как закрывающее облако AI-обобщения. Лучше открытый вопрос или просто факт.

## L5. Темп предложений

Варьировать длину. У Романа в BEST.md встречаются:
- Длинные содержательные предложения (3-4 строки)
- Совсем короткие однострочные ("Это страшно и грустно.", "Сжигаем мосты!")
- Список как один связный абзац или как отдельные строки

Не одинаковая длина абзацев подряд — это AI-метрономия.

## L6. Концовки

Варианты концовки (по BEST.md):
- Открытый вопрос к читателю (без шаблона "если откликается — поставьте 🔥")
- P.S. с уточнением, чувством, отсылкой
- Короткая фраза-выдох ("Каждому своё", "Сжигаем мосты!" — это уместно у самого Романа)
- Просто финальная мысль без отдельной "коды"

НЕ использовать: "Если откликается — поставьте 🔥" в каждом посте, "Сохраните пост, пригодится" подряд несколько раз.

## L7. Лексика для аудитории 40+ — простая, без жаргона ниши

Аудитория Романа — 40–65 лет, читают вечером с телефона после рабочего дня. Они не знают внутреннюю терминологию ниши доходных сайтов. Любой термин, который требует "лезть в гугл", ломает чтение.

**Запрещённые слова без расшифровки** (если они появляются — заменяем простой формулировкой или даём короткий перевод в скобках/одной фразой):

| Жаргон ниши | Чем заменить |
|---|---|
| веб-мастер | "тот, кто делает сайты" / "интернет-предприниматель" |
| домен | "адрес сайта" (если нужно вообще упоминать) |
| дроп / брошенный сайт | "сайт, который когда-то работал, но потом перестал" |
| проседание трафика | "людей стало приходить меньше" |
| трафик | "сколько людей заходит на сайт" |
| семантика | "темы для статей" / "о чём писать" |
| монетизация | "как сайт зарабатывает" |
| админка / WordPress | "панель управления сайтом" / опустить |
| контент-менеджер | "человек, который выкладывает статьи" |
| редактор (как роль) | "редактор, который проверяет тексты" |
| CRM | "таблица клиентов" |
| конверсия | "сколько из 100 дошли до покупки" |
| лид | "заявка" |
| источники дохода (про сайт) | "откуда сайт получает деньги" |
| динамика за 12 месяцев | "как менялись цифры за год" |
| накрутка (трафика) | "цифры на сайте оказались липовые" |
| информационный сайт / инфо-сайт | "сайт со статьями" |

**Правило**: если в посте больше 1 термина из колонки слева — переписать. Если 1 — обязательно перевести в той же или следующей фразе.

**Метафоры из быта** (вместо технических объяснений):
- "Интернет-дача" (уже в VOICE.md) — строим, пользуемся
- "Цифровой ларёк" / "лавка в интернете"
- "Сайт как квартира под сдачу" — есть арендатор-читатель, есть доход с рекламы
- Сравнение с банковским вкладом, депозитом, недвижимостью — это аудитория знает

**Проверка перед публикацией (5 секунд)**: представьте, что пост читает ваша мама вечером после работы. Каждое слово ей понятно с первого раза, без объяснений? Если нет — упрощаем.

## L9. Подача цифр в кейсах — выбор этапа, не финальная цифра

Аудитория 40-65 **не верит цифрам выше ~400 тыс/мес**. Цифры миллион+ воспринимаются как «развод / инфоцыганство», и доверие к посту падает, даже если факт реальный.

**Решение — не подмена, а выбор реального этапа на пути**:

Каждый успешный ученик прошёл путь 30к → 50к → 100к → 200к → 300к → … → текущая. Это **все реальные точки** в его истории. Для L1-L2 серий выбираем тот этап, где он был на цифре, понятной аудитории.

**Правила подачи цифры в кейсе:**

| Финальная цифра кейса | Как подавать в L1-L2 |
|---|---|
| ≤ 400к/мес | Подаём напрямую |
| 400-700к/мес | «Стабильно ≥ 300 тыс» / «больше 300» / «доход в нескольких сотнях тысяч» |
| 700к-1млн/мес | «На этапе истории — 300 тыс, и доход продолжает расти» / «вышел на стабильные 300 тыс, и это не финал» |
| > 1млн/мес (Денис) | «Дошёл до уровня, когда основная работа стала необязательной» (без цифр вообще) / «к этому моменту его доход был в районе 300+ тыс, и продолжал расти» |

**Запрещённые формулировки в L1-L2:**
- «вышел на миллион в месяц»
- «700 тысяч в месяц»
- «1 млн +» как заголовок или хук

**Разрешённые формулировки:**
- «300 тысяч в месяц чистыми» (если такой этап был)
- «доход в несколько сотен тысяч»
- «стабильно ≥ 300 тыс»
- «вышел на хороший доход параллельно с работой» (без цифр)
- «к моменту истории — около 300 тыс, и доход продолжал расти»

**Важно — это не обман.** Это **выбор более раннего этапа реального пути**. Если читатель спросит «а сейчас?», ответ — «сейчас больше, но это уже отдельная история». Это не подмена факта, а адаптация к доверию аудитории.

**Для L4 (углубление в способ)**: финальная цифра разрешена, потому что аудитория уже прогрета и понимает контекст. Но даже в L4 не выносим в заголовок.

## L10. Роль кейса в цепочке — фреймворк использования

Кейсы **не должны жить как самостоятельные серии** — это создаёт ощущение «продажи кейсом». Эффективнее — встраивать кейсы в **подходящий фреймворк** по силе и контексту.

### L10.1. Матрица роли кейса (case_score → формат)

| case_score | Формат | Объём | Cooldown |
|---|---|---|---|
| ≥ 0.65 | **A — главный герой** одного поста | Целый пост | 180 дней (6 мес) |
| 0.60-0.65 | **B — иллюстратор** в посте про принцип | 2-4 предложения вставка | 60 дней (~2 мес) |
| 0.55-0.60 | **C — один из трёх** в зарисовке | 4-6 предложений каждый | 30 дней (~1 мес) |
| < 0.55 | **Не используем для L1-L2** | — | — |

**Запрет:** серии 1-3 поста, посвящённые одному кейсу. Один кейс = максимум один пост, в одной из трёх ролей.

**Кросс-cooldown:** один кейс может быть в разных ролях одновременно (после A через 2 недели — можно C). Запрет только на повтор той же роли в её cooldown-окне.

### L10.2. Структуры Формата A (целый пост про один кейс)

Используются существующие S-схемы из `VOICE.md`:
- **S7** — кейс ученика «обычный человек» (базовая)
- **S4** — хронология «было → потом → вывод»
- **S5** — фейл/разбор (для кейсов с провалом по пути)
- **S6** — наблюдение / метафора (для кейсов с сильным образом)

### L10.3. Структуры Формата B (1 кейс-вставка в пост-принцип)

Варьируем **позицию вставки**:
- В начале как хук («У меня недавно был ученик, который…») → разворот в принцип
- В середине как иллюстрация после принципа
- В конце как доказательство («Один из моих учеников именно так и сделал…»)

### L10.4. Структуры Формата C (2-3 кейса + общий принцип)

5 структур-вариантов между которыми **варьируем**:

| Вариант | Хук / Открытие | Тон |
|---|---|---|
| **C1 — Наблюдение из жизни** | Общее наблюдение про разные результаты у людей вокруг | Рефлексия |
| **C2 — Вопрос-провокация** | Открытый вопрос («Что отличает тех, кто…?») | Исследовательский |
| **C3 — Контраст к стереотипу** | «Все думают X, а на самом деле…» — кейсы доказывают другое | Антииллюзорный |
| **C4 — Стартовая сцена ученика** | Конкретное сообщение/звонок от ученика → «это не первый случай» → ещё 2 кейса | Повествовательный |
| **C5 — Большая метафора** | Метафора (река / дерево / марафон) → 3 типа метафоры в кейсах → возврат | Образный |

**Правила варьирования Формата C:**
- Не повторять одну и ту же структуру 2 раза подряд (проверка по `themes/_cases_usage.json` последние 3 поста Формата C)
- Подбирать структуру по теме когда возможно:
  - Тема «без розовых очков» → C3
  - Сильный образ в теме → C5
  - Тема про результаты → C2
  - Иначе → C1 или C4 по cooldown'у
- Финал варьируем (по L6): открытый вопрос / факт / тёплая фраза / P.S.

### L10.5. Структура Формата C-постов (обязательная)

Каждый пост Формата C состоит из 7 частей:
1. **Наблюдение в жизни** (короткое введение в рамку — не «сразу про учеников»)
2. **Углубление наблюдения / переход к принципу**
3. **Переход к ученикам** («то же самое я вижу у учеников»)
4. **Кейс 1 + дополнение/наблюдение** (после кейса — Роман укрепляет свою мысль)
5. **Кейс 2 + дополнение/наблюдение**
6. **Кейс 3 + дополнение/наблюдение**
7. **Финал** — вывод или открытый вопрос

**Запрет на «сухое перечисление 3 кейсов без дополнений»** — это убивает живость.

### L10.6. Принцип: кейс подкрепляет, а не продаёт

Если пост звучит как «вот человек, и вы тоже можете заработать» — это продажа.
Если «вот принцип, и кейс показывает, что он работает на разных людях» — это доверие через факт.

## L8. Баланс уровней глубины контента (L1-L4)

Каждый пост имеет «уровень глубины» по лестнице осознанности — от L1 («разрешить мысль») до L4 («погружение в способ»). Полная таксономия — в `knowledge/CONTENT_LEVELS.md`.

**Целевая доля в потоке постов:**

| Уровень | Что | Доля |
|---|---|---|
| **L1** | «Разрешить мысль» — истории, рефлексии, «я такой же» | 40-50% |
| **L2** | «Разрешить категорию» — рамка, метафора, «что бывает» | 30-35% |
| L3 | «Сравнить классы» — что подходит вам | 10-15% |
| L4 | «Погружение в способ» — детальный кейс / чек-лист | 5-10% |

**Правила для серии (2-3 поста):**

1. Серия должна быть преимущественно **L1-L2**. Если 2+ поста уходят на L3-L4 — это «прыжок через ступени». Аудитория отваливается.
2. Допустимы смешения: L1+L2 (рамка → история), L2+L4 (рамка → один углублённый пример).
3. Запрещено: 3 поста L4 подряд в одной серии. L4-серии — точечные «премиум-погружения» раз в 1-2 месяца, после нескольких L1-L2.
4. **Один и тот же материал корпуса можно подать на разных уровнях.** Кейс Алексея с механикой = L4. Тот же Алексей в «трёх человеках, у которых пошло» = L1. Уровень = угол подачи, а не тема.

**Перед предложением структуры серии:**

- Явно проставить уровень каждому посту (L1/L2/L3/L4).
- Если все 2-3 поста L3-L4 — пересмотреть углы или сменить тему.

**Symptom-test на «перепрыг через ступени»:**

Если в постах серии много инструкций («проверьте на три вещи», «вот шаги»), детальных цифр кейсов или технических терминов конкретного способа — это L4. Замена на L1-L2: убрать механику, оставить человека и состояние.
