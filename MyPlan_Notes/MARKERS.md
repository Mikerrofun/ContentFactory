# Маркеры: как это работает

Детерминированная (без LLM) проверка текста на «человечность» и «адаптивность». Используется как авто-метрика валидации (quality-gate).

---

## Что это

4 словаря в `knowledge/markers/`:
- `biomarkers.md` — возраст, семья, профессия, тип занятости;
- `emotional_markers.md` — страхи, тяжесть, сомнения;
- `fear_markers.md` — чем закрывается страх (7 групп);
- `anti_markers.md` — жаргон/непонимание (штраф).

Каждый словарь — это **группы синонимов**, а не просто список слов.

---

## Шаг 1. Парсинг md → группы синонимов

`markers.py` читает `.md` как текст:
- `## Заголовок` → категория;
- `- строка` → маркер;
- `«фраза»` → конкретный маркер;
- `«вариант А» / «вариант Б»` → **одна группа** (совпал любой вариант → +1 группе).

Пример из `biomarkers.md`:
```
## Возраст
- N лет (30–80 + «лет»)
- «в 40», «в 50», «пенсионер»
```
→ группа «возраст» с вариантами.

---

## Шаг 2. Сверка поста со словарём

Для каждого маркера строится **regex по границам слова** (чтобы «лид» не.match «лидер»), с учётом русских окончаний («врач» → «врача»).

`count_marker_matches`: если хоть один вариант группы встретился в тексте → **+1.0** группе (каждая группа считается один раз, чтобы не раздувать счёт).

Опционально L3: если точного совпадения нет, но эмбеддинг маркера близок к какому-то предложению (≥0.65) → +0.7. Это фолбэк, не основной путь.

---

## Шаг 3. Метрики 0..1

- **`human_factor`** = `1 − exp(−count/5)`:
  - 0 маркеров → 0.0
  - 5 → 0.63
  - 10 → 0.86
  - (насыщающая кривая: чем больше, тем ближе к 1)
- **`adaptability`** = (сколько групп страхов закрыто ÷ 3, макс 1) − штраф за жаргон (÷5, макс 0.5) − штраф за «высокий доход без био» (0.1) → clamp 0..1.

---

## Пример

Пост: «В 45 лет я, врач с двумя детьми, боялась, что не справлюсь.»
- возраст «45 лет» → +1
- профессия «врач» → +1
- семья «двое детей» → +1
- страх «боялась, что не справлюсь» → +1
- count ≈ 4 → `human_factor ≈ 0.55`

Пост: «Монетизация трафика, конверсия, лид, семантика, домен.»
- anti_markers (жаргон) → несколько → `adaptability` падает, `human_factor ≈ 0`.

---

## Как используется в новой системе

Только как **авто-метрика валидации (quality-gate, п. 6a)**:
- считается локально, без LLM, бесплатно и быстро;
- посты с низким `human_factor` / высоким жаргоном → warn/fail;
- LLM подключается **только в серой зоне** (метрика на пороге) — один дешёвый вызов «человечно / нет».

**Не используется** для скоринга чанков (там выработка по фактам) и для типов чанков.

---

## Важные оговорки

- Маркеры — **прокси, не правда**: высокий `human_factor` ≠ хороший пост (можно «набить» маркерами), низкий ≠ плохой (сухой факт бывает уместен).
- Это **мягкий сигнал** для подсказки/флага, а не приговор.
- Сами фразы из словаря в текст **не вставляются** — они только считаются. Улучшение делает регенерация/копирайтер/LLM, а маркер лишь говорит «сделай человечнее».
- Порог «хорошего» `human_factor` калибруется на золотых постах.
