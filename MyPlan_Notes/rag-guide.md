# RAG и развитие проекта

Стартовая база позволяет запустить весь путь от вопроса до черновика на публичных выдержках. Дополнительные модули показывают, какие задачи уже решались при развитии редакторского процесса. Код находится в src/contentgen, обычный запуск описан в README.md.

## Одна проверка на своих данных

После создания индекса откройте терминал в проекте, задайте PYTHONPATH=src и выполните команды.

```sh
uv run --frozen python -c 'from contentgen.discovery import discover_seed_themes; print([(t.stem_chunk_id, t.seed_origin, round(t.score, 2)) for t in discover_seed_themes(limit=3)])'
uv run --frozen python -c 'from contentgen.voice_anchors import get_voice_anchors; print(get_voice_anchors("реакция читателей", pillar="PROOF", min_chunk_len=30, min_score=0.3, max_k=2))'
uv run --frozen python -c 'from contentgen.mcp_server import corpus_status; print(corpus_status())'
```

Первая команда берёт темы из knowledge/FACTS.md и ищет материал в индексе. Вторая извлекает речевые образцы. Для короткого демонстрационного корпуса порог длины задан явно. На полном тексте стандартный минимум равен 500 символам. Третья команда даёт объём и состав корпуса. Каждое значение score описывает свой этап. Косинусное сходство означает близость формулировок. Редактор проверяет, подтверждает ли найденный отрывок конкретное утверждение.

## Путь материала

1. **Подготовка.** index.py читает 12 заранее отобранных фрагментов и сохраняет исходные ссылки. Отдельный путь для длинных текстов — ingest.py, chunker.py и meta_extractor.py. Текст делится по абзацам, короткие фрагменты отсеиваются, длинные нарезаются до 500 слов. Внешняя модель определяет рубрику, тональность, тему и признаки. На вход передаются только предназначенные для обработки файлы. Переменная CONTENTGEN_META_MODEL выбирает модель разметки. На малой подборке разметка уже задана, расходов на этот этап нет.
2. **Хранение и поиск.** embeddings.py строит 384-мерные векторы MiniLM, storage.py сохраняет SQLite и NumPy, retrieve.py ищет ближайшие записи с фильтрами. Порядок строк SQLite соответствует строкам матрицы. При замене источника требуется сохранять это соответствие. Для тестового индекса достаточно одной последовательной сборки. Для одновременных обновлений следует продумать транзакции или версии индекса и восстановление при прерывании между записью SQLite и NumPy.
3. **Тема из материалов.** discovery.py умеет двигаться двумя путями. Поиск от фрагмента ранжирует развёрнутые отрывки по качеству основы, соседям, разнообразию источников и рубрике. Поиск от темы начинает с набора исходных фактов, затем проверяет близость и полноту поддержки. Короткие публичные выдержки специально подходят для второго пути. themes_history.py хранит историю и временно исключает недавно использованные основы. Чередование рубрик, три самостоятельные идеи и выбор копирайтера предстоит реализовать.
4. **Кейс как источник.** cases_index.py разбирает разделы карточки, add_case.py извлекает поля, case_patch.py дополняет описание на месте. upgrade_diagnostics.py ищет, каких подтверждающих деталей не хватает. cases_usage.py учитывает, в какой роли история уже использована. format_selector.py выбирает способ включения истории. Рабочие карточки людей не требуются для изучения алгоритма. При недостаточной фактуре код может вернуть пустую подборку.
5. **Язык и пригодность.** Четыре словаря в knowledge/markers содержат общие слова и группы синонимов. markers.py различает группы признаков, markers_embedded.py умеет дополнительно сравнивать фразы по смыслу, markers_extractor.py предлагает новые маркеры по выбранным текстам. Эти признаки помогают ранжировать материал. Они не удостоверяют правдивость истории. Часть извлечения эмоциональных кандидатов остаётся нереализованной.
6. **Авторский голос и контроль.** voice_anchors.py подбирает примеры по теме, рубрике и тону и отсекает почти одинаковые тексты. draft.py в базовом режиме использует VOICE.md. Динамическое добавление подобранных образцов в браузерный сценарий остаётся решением разработчика. post_quality.py проверяет длину, словарь, числа и при наличии образца — близость интонации. Совпадение числа с базой фактов не доказывает, что оно относится к правильному событию.
7. **Возврат финала.** final_posts.py сохраняет редакцию материала и переиндексирует итог. publications.py ведёт журнал публикаций и использования тем. Обучение по парам правок, надёжное хранение разных версий, учёт противоречий и отмена действующего правила — часть задания. Финал полезен как пример голоса, однако его новые утверждения требуют собственных источников.
8. **Инструментальный интерфейс.** mcp_server.py предоставляет операции поиска, наполнения корпуса, подбора кейсов, обнаружения тем, оценки и записи финала редакторским клиентам через stdio. Запуск: `uv run --frozen python -m contentgen.mcp_server` после задания PYTHONPATH=src. Доступ к инструментам изменения данных предоставляйте только доверенному локальному процессу. Браузерному приложению понадобится собственная авторизация.

## Проверки при дальнейшем развитии

На фиксированной свежей теме сравните стартовый поиск с изменённым. Сохраните найденные источники и проверьте по отдельности, попал ли подтверждающий отрывок в выдачу и использован ли он правильно в черновике. Добавление большего числа похожих фрагментов может вытеснить независимые источники. Для подбора голоса проверьте отсутствие дубликатов и отделяйте тональность примера от фактов о событии. Для механизма правок измеряйте частоту повторной редакции одного приёма на новых постах и цену ошибочного обобщения в другой рубрике.

Модульные тесты используют контролируемые ответы модели и векторы. Они показывают воспроизводимое поведение кода. Три команды выше выполняют отдельную проверку на реальной поисковой модели. Готовность текста к публикации оценивает копирайтер.

Рабочий индекс включает текст источников и метаданные; готовую базу и векторы создайте командой index.py из переданных материалов. Векторы маркеров пересчитываются из четырёх словарей. Перенос приватного индекса перенёс бы и исходные тексты.
