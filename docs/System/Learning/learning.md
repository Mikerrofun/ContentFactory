# Самообучение (Этап 3)

Статус: черновик v2. Самая сложная часть. Связка: валидация → обучение → промпт (Этап 4) → учёт (Этап 5).

Главное:
1. База знаний = **3 слоя: правила / веса / эпизоды.** Каждое решение трогает все три.
2. **Гибрид:** правила-условия + немного агрегатных весов.
3. **Скоуп 2 уровня:** глобально / тип поста.
4. **Исключения** с TTL по правкам, не генерализуются.
5. **Отмена = вето-вес** (не удаление), влияет на будущее, восстановимо.
6. Веса подстраиваются по **preference** (выбор 1/3), не по «ближе к эталону».

Файлы-источники: `docs/Info_ForGeneration/{VOICE_FINGERPRINT,LESSONS,STYLE_TRANSLATION}.md`, `Архив/BEST.docx`, `docs/System/Validation/validationRecon.md` (17 метрик).

---

## 1. Три слоя

### Слой 1 — Правила
Условные, скоуп (глобально/тип), версионируемые. Поля:
- `rule_id`, `text` (ЕСЛИ... ТО...), `scope` (global|type), `type` (если type)
- `support` (согласованных правок в окне), `conflict` (bool)
- `weight_delta` (что сдвинуло в весах), `version`, `status` (active/veto/candidate/exception)
- `created_at`, `source_episodes[]`

### Слой 2 — Веса
Пара агрегатов (стиль-матч, ритм, human, fact_recall...). Поля:
- `metric`, `value` (0..1), `history[]` (кто/когда менял)
- Меняются медленно, демпфирование.

### Слой 3 — Эпизоды
Один эпизод = одно решение:
- `episode_id`, `post_id`, `type`, `tact_flags`
- `draft` → `final`, `diff` (по тактам)
- `choice` (1/3), `metrics_snapshot` (17 на draft и final)
- `date`, `rule_versions`, `weight_versions`

---

## 2. Как решение трогает все 3 слоя (пошагово)

1. **Diff** (что изменил копирайтер) → классификация каждой правки:
   - совпала с активным правилом → `support++` правила;
   - совпала с парой STYLE_TRANSLATION → +пара (словарь);
   - новое → кандидат-исключение (`support=1`, TTL);
   - противоречит активному правилу → `conflict++`, НЕ применяем, ждём.
2. **Preference:** выбранный пост был лучше по метрике X (из 17) → `вес X += η·delta` (η — демпфирование, напр. 0.05).
3. **Эпизод** пишется целиком (снапшот).
Итог: правила (support/conflict) + веса (delta) + эпизоды обновлены атомарно.

---

## 3. Исключения vs правила (детально)

Кандидат: `support` + `scope` + `conflict` + `age_in_edits`.
- `support < 3` ИЛИ `conflict` → **исключение**: узкий скоуп, не генерализуется, `TTL` (напр. 20 правок). После TTL → архив (не в промпт).
- `support ≥ 3` И `conflict=0` → **правило**.
- Исключение набрало support в TTL → повышается в правило.

**TTL по правкам, не дням:** исключение живёт N правок копирайтера. Зачем: чтобы редкие правки не копились месяцами и не превращались в кучу правил.

---

## 4. Порог правила (детально)

- Окно последних **N правок** (не дней).
- В окне: `support` согласованных + `conflict`.
- LLM оценивает **силу влияния** (1-5): насколько правило меняет пост. Слабые (<3) не идут в правила даже при support.
- `support≥3` И `conflict=0` И `сила≥3` → правило.
- Редкие/растянутые → исключение с TTL.

---

## 5. Веса — детально (ответ на «мало метрик»)

- Веса = веса 17 метрик при выборе лучшей из 5 генераций. НЕ оценка поста.
- Подстраиваются по **preference** (выбор копирайтера), не по «ближе к эталону».
- **Коридор, не точка** (mode collapse).
- Демпфирование η: вес меняется на `η·(target−current)`, η=0.05.
- 13 качества + 4 диверсити (14-17): диверсити не дают схлопнуться.
- `weight_delta` у правила: откат правила → откат только его delta.

---

## 6. Откат правила и весов (детально)

- Правило хранит `weight_delta` (вектор изменений, что оно сдвинуло).
- Откат правила → вычитаем его `weight_delta` из весов.
- 3 правила двигали один вес → история deltas по каждому; откат нужного.
- Откат по метрикам: правило, ухудшившее gold-метрики → авто-откат (veto).

---

## 7. Отмена = вето-вес (детально)

- Ставит `status=veto` (не удаляет).
- Сразу не применяется в промпте.
- Пишет «не учи в эту сторону»: будущие правки в ту же сторону → игнор (не support++).
- Само → эпизод (восстановимо).
- Вычитает свой `weight_delta`.
- Если позже подтверждений больше, чем ветов → `status=active`.

---

## 8. Скоуп

2 уровня: global / type. Такт не скоуп (привязан к типу).
- Global: убрать длинное тире (Правило 3/4).
- Type: вступление деловое→разговорное в METHOD.

---

## 9. Защита от переобучения (детально)

- Скоуп: правило не лезет в другие типы.
- Версия правил/стиля в эпизоде → A/B чистый.
- Откат по метрикам на gold.
- TTL исключений.
- Коридоры метрик (ритм/словарь).
- Демпфирование весов.
- Preference, не «идеал».

---

## 10. Связка с 5 типами и 3 постами

- 3 поста одного типа → выбор лучшего → preference типа.
- Правки type-такта → правила типа; общие такты (Хук/Финал/Ядро-структура) → global.
- Прокачка типа + глобальная.
