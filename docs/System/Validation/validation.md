# 5-тактная валидация текста (Этап 2)

Статус: черновик v1. Связка: валидация ↔ обучение. Дальше: самообучение → промпт+самокритика → учёт после человека.

Главное:
1. Пост = 5 тактов.
2. **Такты бывают общие (у всех типов) и type-specific (только у своего типа).**
3. Правка type-такта → учим этот тип. Правка общего такта → учим всю систему.
4. Валидация: детерминированные чекеры + лёгкие модели (OpenRouter, копейки).
5. Выход: вердикт + флаги по тактам.

---

## 1. 5 тактов

| № | Такт | Общий/Type | Что проверяем |
|---|---|---|---|
| 1 | ХУК | **общий** | цепляет, завершён, ≤60 симв (L2, Правило 7) |
| 2 | РАМКА | type-specific | контекст/анти-иллюзия/кто герой (VOICE §5.1) |
| 3 | ЯДРО | type-specific | 3-5 действий/аргументов, факты из бандла |
| 4 | ДОКАЗАТЕЛЬСТВО | type-specific | кейс/цифра/артефакт (L10, ≤400к L9) |
| 5 | ФИНАЛ | **общий** | один closing-приём (Правило 20), арка (8), CTA (10) |

Общие такты (1, 5) одинаковы для всех типов. Type-такты (2,3,4) зависят от типа поста.

---

## 2. Такты по 5 типам постов

| Тип поста | Такт 2 РАМКА | Такт 3 ЯДРО | Такт 4 ДОКАЗАТЕЛЬСТВО |
|---|---|---|---|
| HUMAN-история | личная сцена | 1 эпизод → вывод | эмоция/деталь |
| PROOF-кейс | кто герой, контекст | 3-5 шагов | результат + fear_closed |
| METHOD-чеклист | рамка в 1-2 строки | 5-9 пунктов | 1 короткий пример |
| TRUST-границы | позиция | 5-9 правил/запретов | почему (по строке) |
| PROOF-мой путь | факт автора | 2-4 факта | что это значит для вас |

Пример: у PROOF-кейса такт 4 = результат кейса; у METHOD такт 4 = пример к пунктам. Такт 4 type-specific → его правки учат только этот тип.

---

## 3. Как валидируем

- **Детерминированные чекеры** (regex/эмбеддинг, без LLM): длина, жаргон (anti_markers), AI-маркеры (L4), human_factor, adaptability, number-guard (FACTS/PRODUCT_FACTS), 5-тактная полнота, близость к эталону стиля.
- **Лёгкие LLM** (OpenRouter, дешёвые): смысл такта, одна ясная мысль, нет выдумок, соответствие стилю. Флаги по тактам.
- LLM подключается в серой зоне метрик (спорно) — экономим.

---

## 4. Выход gate

- `verdict`: pass / warn / fail.
- `tact_flags[]`: по каждому такту (ok/warn/fail + причина).
- `fix_hint`: что чинить (для адресной перегенерации одного такта, не всего поста).
- Пишется в журнал: версия промпта, версия стиля, тип поста, флаги.

Fail → не отправляется. Warn → можно, но помечено. Fix_hint → адресная перегенерация такта.

---

## 5. Пороги

- Калибруем на золотых постах (BEST 67 + финалы копирайтера).
- Стартовые фикс-пороги подбираем при тестировании.
- pass-порог ≈ 10-15 перцентиль золотых (хуже 85% золотых → fail).

---

## 6. Связка с обучением (мост к Этапу 3)

- Правка **type-такта** (2/3/4) → дистилляция в правила **этого типа** поста.
- Правка **общего такта** (1/5) → дистилляция в **общие** правила (вся система).
- Выбор лучшего из 3 (один тип) → preference-сигнал для этого типа.
- Такт-флаги копятся → метрики улучшения по типам и общие.
