# Учёт после человека + 3 поста/день (Этап 5)

Статус: черновик v1. Связка: Этап 4 (генерация) → Этап 5 (3 поста + учёт) → Этап 3 (обучение) → Этап 1 (износ чанков).

Главное:
1. Утро: **3 разных якоря одного типа** → на каждый 5 генераций (15 всего).
2. Выбор лучшей из 5 — по метрикам + LLM-оценка (паттерн самокритики, разные модели).
3. 3 лучших → копирайтеру. Он выбирает/правит.
4. **После полных правок человека** → учёт + подбивка (Этап 3) + износ чанков.
5. Износ: knowledge/case полный; факты/остальные cooldown; золотые без cooldown.

---

## 1. Утренний прогон (до человека)

1. Система берёт **тип поста** (ротация по взятым, не план).
2. **3 разных якоря** из ядра (knowledge/case) этого типа.
3. На каждый якорь — свой бандл (5 слотов, Этап 1).
4. На каждый — **5 генераций** (Этап 4, разные углы).
5. Выбор лучшей из 5: метрики (17) + LLM-оценка (критик, лёгкая модель).
6. 3 лучших (по одному на якорь) → копирайтеру.
7. **Учёт НЕ делаем** (бриф: учёт после человека).

---

## 2. Выбор лучшей из 5 (подробно)

На каждый якорь — 5 генераций. Для каждой считаем 17 метрик (`docs/System/Metrics/metrics.md`) + LLM-оценку критик-моделью (лёгкая, OpenRouter).

Как оцениваем:
1. **Детерм-метрики** (1,2,3,4,6,7,11,12,13,14,15,16,17) — локально, дёшево.
2. **LLM-метрики** (5,8) — критик смотрит пост + факты.
3. **LLM-ранжирование** — критик сравнивает 5 вариантов одного якоря, возвращает порядок + причины.
4. **Сводный балл** = взвешенная сумма 17 метрик (веса из Этапа 3) + LLM-ранг.
5. Лучшая (макс балл, gate pass) → в 3 финальных.

Итог оценок 5 вариантов → в учёт (не дублировать): идёт в [ВЫБ] и [ОБУЧ] (подбивка весов/правил, Этап 3). Разные модели: генерация сильная, критик лёгкая.

Связка: тот же паттерн, что самокритика (Этап 4). Метрики — `docs/System/Metrics/metrics.md`.

---

## 3. После человека (учёт)

После полных правок копирайтера:
1. **Эпизод** (полный, Этап 3): draft/final/diff/choice/17 метрик/версии.
2. **Правки → база знаний** (Этап 3): сразу пополняем (словарь/кандидаты), правила не сразу (подбивка, могут уничтожаться).
3. **Износ чанков** (Этап 1):
   - knowledge/case — полный износ использованных.
   - факты/остальные — cooldown.
   - золотые/постоянные — без cooldown.
4. **Подбивка системы** (Этап 3): веса/правила по preference.

---

## 4. Износ по типам (детально)

| Тип | Износ | Cooldown |
|---|---|---|
| knowledge | по фактам (facts_used) | — |
| case | полный после использования | да (долгий) |
| fact | обычный | да |
| swipe | обычный | да |
| voice (золотые) | без | нет |
| audience | без | нет |

---

## 5. Что фиксируем
- 3 якоря, 15 генераций, оценки.
- Выбранный пост + diff.
- Эпизод + версии правил/стиля.
- Износ по чанкам бандла.

---

## 6. Связка с Этапом 3
- Эпизод → 3 слоя (правила/веса/эпизоды).
- Правки сразу пополняют базу; правила через подбивку (могут уничтожаться/восстанавливаться).
- Preference (выбор 1/3) → веса.
