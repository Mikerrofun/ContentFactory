# LLM-заполняемые поля чанков (v2)

Эти поля при нарезке `null`, заполняются отдельной итерацией индексации. Ниже — не только «что это», но и **как поле встроено в систему**: в сборку бандла (генерация), в метрики/валидацию, в износ. В конце — вердикт по каждому (оставить/выкинуть).

Детерминированные поля (`canPublish`, `emotion`, `pillar`, `format`, `whyItWorks`, `structure`, `patternsToBorrow`, `doNotCopy`, `text`, `sourcePath`, `embedding`) LLM не трогает.

## Как поля встроены в систему (общая карта)

**Сборка бандла (5 слотов + гард + узнавание):**
1. Якорь — ядро (knowledge/case).
2. Факты-доноры — knowledge-соседи (MMR, порог 0.55) ~10–12.
3. Кейс-доказательство — case по `fearClosed` (1–2).
4. Voice-эталоны — best по `sScheme`+тон (2–3).
5. Морф-шаблон — swipe по `pillar`+`format` (1).
+ гард (fact/PRODUCT_FACTS) + узнавание (audience по `fearType`, 2–3).

**Метрики (из `metrics.md`):** `adaptability` (3) — страхи; `human_factor` (2) — bio/emotional; `auto_score` (1) — anti-маркеры; `Structure Repetition` (14) — s_scheme/format; `Fact-Recall` (7) — facts.

**Износ:** knowledge по фактам, case полный, эталоны почти нет.

---

## 1. `case.fearClosed` (Json) — только `case`

**Что это:** массив номеров страхов (1–7), которые кейс закрывает. 7 страхов: 1 «не справлюсь», 2 «обманут», 3 «впустую потрачу», 4 «нет времени», 5 «нет компьютера», 6 «поздно», 7 «стыдно». Пример `[1,6]`.

**Как определяет LLM:** вход — `text` кейса + признаки из `fear_markers.md`; вопрос — «какие из 7 страхов закрывает кейс? верни массив 1–7»; выход — `number[]` ⊂ {1..7}.

**Как встроено:**
- Генерация: слот 3 — под страх темы тянем case с этим номером (точнее косинуса); кейсы с >1 страхом выше.
- Метрики: `adaptability` (3) = `(fear/3) − жаргон`; источник `fear_markers`. Кейс без страхов = слабый PROOF.
- Износ: case расходуется полностью после использования.

**Вердикт:** **оставить** (ядро подбора доказательства).

## 2. `best.sScheme` (String) — только `best`

**Что это:** код структурного шаблона `S1…S15` (скелет из VOICE.md), напр. `S4` «хронология/лестница».

**Как определяет LLM:** вход — `text` + перечень S1–S15 со скелетами; вопрос — «какой S-схеме соответствует пост? верни код»; выход — `S1..S15` | null.

**Как встроено:**
- Генерация: слот 4 — 2–3 эталона best с той же `sScheme` → few-shot по структуре (модель повторяет архитектуру, наполняя своим).
- Метрики: `Structure Repetition` (14) — «тот же скелет N постов подряд», по `s_scheme`+история. [ВЫБ]/[УЧ]/[ОБУЧ].

**Вердикт:** **оставить** (структурный few-shot + разнообразие).

## 3. `best.closingType` (String) — только `best`

**Что это:** тип финала: лестница / факторы / мостик / CTA / арка.

**Как определяет LLM:** вход — `text` + перечень типов; вопрос — «какой тип финала? верни один из списка»; выход — string | null.

**Как встроено:**
- Генерация: слот 4 — подбор эталона по типу финала (модель видит разные концовки).
- Метрики/разнообразие: вместе с `sScheme` в `Structure Repetition` (14), чтобы финалы не повторялись.

**Вердикт:** **оставить** (дёшево, улучшает разнообразие; можно опционально).

## 4. `best.markers` (Json) — только `best`

**Что это:** `{fear:[],bio:[],emotional:[],anti:[]}` — какие маркеры из 4 словарей реально есть в тексте эталона.

**Как определяет:** можно **детерминированно (regex по словарям)** — LLM не обязателен. Если LLM: вход — `text` + 4 словаря; вопрос — «верни объект с 4 массивами найденных маркеров».

**Как встроено:**
- Метрики: `human_factor` (2, bio+emotional), `auto_score` (1, anti), `adaptability` (3, fear). [В]/[ВЫБ]/[ОБУЧ].
- Генерация: не слот; фильтр/приоритет эталонов best (мало `anti`, есть `bio/emotional`).

**Вердикт:** **оставить**, но считать **детерминированно (regex)**; LLM-вариант опционален.

## 5. `audience.fearType` (Int) — только `audience`

**Что это:** номер страха 1–7 для фразы (только у `emotion` = страх/скрытый страх; иначе null).

**Как определяет LLM:** вход — `text` фразы + 7 страхов; вопрос — «какой страх 1–7 выражает фраза? верни число или null»; выход — int | null.

**Как встроено:**
- Генерация: слот «узнавание» — 2–3 фразы audience с тем же `fearType`, что страх темы → дословно в текст.
- Метрики: `adaptability` (3) — покрытие страха темы фразами.

**Вердикт:** **оставить** (узнавание + adaptability).

## 6. `knowledge.facts` / `knowledge.topic` — только `knowledge` (БУДУЩЕЕ)

> Тип `knowledge` появится позже (источник из бота). Сейчас не в этой итерации.

- `facts` (Json): 3–7 атомарных фактов → донор (слот 2) + износ по фактам + `Fact-Recall` (7). Вопрос: «извлеки 3–7 фактов, массив строк».
- `topic` (String): тема/ниша (опц. фильтр). Вопрос: «тема одним словом».

**Вердикт:** оставить (будущее).

## Вердикт: что оставить / что выкинуть

| Поле | Тип | Вердикт | Почему |
|---|---|---|---|
| `fearClosed` | case | оставить | ядро подбора case + adaptability |
| `sScheme` | best | оставить | few-shot структуры + метрика 14 |
| `closingType` | best | оставить | разнообразие финалов (дёшево) |
| `markers` | best | оставить (regex) | метрики 1/2/3; LLM не нужен |
| `fearType` | audience | оставить | узнавание + adaptability |
| `facts` | knowledge | оставить (будущее) | донор + износ |
| `topic` | knowledge | оставить опц. (будущее) | фильтр/метрика |

Ничего не выкидываем — все поля имеют ясную роль (генерация и/или метрики). Единственное уточнение: `markers` дешевле считать regex, а не LLM.

## Что LLM НЕ заполняет (детерминировано)

`canPublish` (fact), `emotion` (audience), `pillar`/`format` (best/swipe), `whyItWorks/structure/patternsToBorrow/doNotCopy` (swipe), `text`, `sourcePath`, `embedding`. `isHumanFinal` (best) — человек.

## Общий порядок прогона

1. Выбрать тип и поле.
2. Для каждого чанка: `text` + справочник → вопрос модели (или regex для markers) → ответ.
3. Валидировать по допустимому набору (иначе `null`/повтор).
4. Записать в поле (upsert); при необходимости — пересчёт эмбеддинга.
