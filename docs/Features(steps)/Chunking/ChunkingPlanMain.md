# ChunkingPlan — план нарезки контент-базы (Этап 1)

Статус: черновик v1, на согласование.
Старт: простые типы. Порядок блоков: **fact → voice → case**. Сложные (knowledge / swipe / audience) — позже.

Источники: `docs/Facts:Case:Best/*`, `docs/Info_ForGeneration/*`.
Сущности: `prisma/schema.prisma` (`ChunkType`, `Chunk`).
Док-контекст: `docs/System/Chunks/chunks.md`, `chunkPresentation.md`.

---

## 0. Общие решения (на все типы)

1. **Векторы — отдельная итерация.** В этой итерации: создаём поля + пишем чанки (JSON/БД). Эмбеддинги НЕ считаем.
2. **ID чанка — человекочитаемый, он же PK:** `F-0001`, `VK-P-0001`, `CASE_0001`. Детерминизм (одинаковый вход → одинаковый чанк).
3. **Текст храним очищенным.** Снимаем экранирование markdown (`\##`→`##`, `\-`→`-`, `\---`→`---`, `\[`→`[`, `\]`→`]`, `\~`→`~`), нормализуем пробелы/строки. Готовый модуль `src/core/cleanup` в репо **не развёрнут** (есть только `index.ts`) — для этих файлов достаточно де-экранирования + нормализации; правила из заметки «Очистка» применяем частично.
4. **Векторное поле (`vectorText`)** — что именно уходит в эмбеддинг, задаём для каждого типа отдельно (см. блоки). Остальные поля — статичные метаданные, в векторном поиске НЕ участвуют.
5. **Износ/деплешн (по решению):** поле `depletion` стартует с **1.0** (ресурс полный) и **снижается** по мере использования. Для `case` добавляется `cooldownUntil` (ставится при использовании, не при индексации). `status = active` при создании.
   - ⚠️ Требует правки prisma: `depletion Float @default(1.0)` (сейчас `@default(0)`) + семантика «1 = полный, 0 = исчерпан».
6. **sourcePath** = путь к файлу-источнику; **sourceUrl** — если есть в карточке (`source_link`, puzat.ru и т.п.).

### Куда складываем чанки
- Дерево: `data/chunks/<тип>/<chunk_id>.json` (как в заметке).
- Запись в БД — отдельным шагом (`chunk:load --apply`), вручную, dry-run по умолчанию.

## Порядок и поток (по блокам)

```
БЛОК fact:  FACTS.md + PRODUCT_FACTS.md → clean → map → data/chunks/fact/*.json → validate
БЛОК voice: BEST.md (2 вида заголовков)   → clean → map → data/chunks/voice/*.json → validate
БЛОК case:  CASE.md (отделить шапку)       → clean → map → data/chunks/case/*.json → validate
```

Каждый блок: парс → очистка → маппинг полей → запись JSON → валидация. БД — отдельно, в конце, вручную.

## Что НЕ чанкуем (читается целиком в промпт)
`GUARDRAILS.md`, `PILLARS.md`, `STANDARD.md`, `VOICE.md`, `CONTENT_LEVELS.md`, `LESSONS.md`, `STYLE_TRANSLATION.md`, `VOICE_FINGERPRINT.md`, `Markers/*`.

## Схема БД — что добавить в prisma
- `Chunk.depletion` → `@default(1.0)` (семантика 1=полный → 0=исчерпан).
- Новые поля: `canPublish`, `scene`, `emotion`, `tags[]`, `platform`, `postDate`, `goal`, `context`, `successMetric`.
- `chunkEmbedding` (pgvector) — добавим в итерации векторов.
