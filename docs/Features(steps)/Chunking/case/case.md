### Подводные камни
1. **Многострочные значения** — `source_proof`, `START`, `ACTIONS`, `RESULT`, `KEY INSIGHT` идут списком/нумерацией; строки-продолжения без маркера поля клеятся к текущему полю.
2. **Пропущенные поля** — у части кейсов нет `START`/`ACTIONS`/`RESULT`/`pillar` и т.д. → `null`/`[]`.
3. **Дубли** — `CASE_0067` ≈ `CASE_0003` (Александр Чирков, те же цифры). Решить: дедуп или оставить оба.
4. **Экранирование markdown** — `\~`, `---` (внутри значений), `1\.` и т.п.

## 3. Правила парсинга

1. Пропустить всё до первого `## CASE_`.
2. Новая карточка — строка `^## CASE_`.
3. Маркер поля — `^([A-Za-zА-Яа-я ()\-0-9]+):\s?(.*)$` при whitelist известных имён (см. таблицу). Только они открывают поле.
4. Продолжение — строка без маркера известного поля (в т.ч. `• …`, `1. …`, пустые) → к текущему полю.
5. Пустое значение → `null`/`[]`.
6. `id` — из заголовка (`CASE_0001`); `hero` — имя из заголовка; `resultHeadline` — хвост заголовка после второго `---`.

## 5. Схема данных чанка `case` (JSON)

Принцип: как у `fact` — не режем сильно, весь контент в `text` (он же в вектор). Отдельными полями — только нужное для фильтрации/поведения.

```jsonc
{
  "id": "CASE_0001",
  "type": "case",
  "text": "Кто: замдиректора… Было: 0 руб/мес… Цель: уйти с найма… Действия: 1) … 2) … Результат: 80 000 руб/мес… Вывод: … Шаг читателю: …", // весь кейс → в вектор
  "hero": "Жанибек Кенжебеков",       // имя из заголовка
  "topic": "сайты",
  "pillar": "PROOF",
  "sourceUrl": "https://puzat.ru/case/zhanibek-kenzhebekov",
  "sourcePath": "docs/Facts:Case:Best/CASE.md",
  "fearClosed": null,                  // заполнит LLM по fear_markers позже
  "cooldownUntil": null,               // ставится при использовании
  "addedAt": "<ISO>"
}
```

### Типы полей
| Поле | Тип | Источник |
|---|---|---|
| `id` | string PK | `CASE_####` |
| `type` | enum | `case` |
| `text` | string | весь кейс (START+GOAL+ACTIONS+RESULT+INSIGHT+STEP), очищенный |
| `hero` | string | имя из заголовка |
| `topic` | string\|null | `topic` |
| `pillar` | string\|null | `pillar` |
| `sourceUrl` | string\|null | `source_link` |
| `sourcePath` | string | путь |
| `fearClosed` | string[]\|null | позже (LLM) |
| `cooldownUntil` | string\|null | при использовании |

### Что НЕ храним отдельно
`steps / result / heroBio / sourceProof / incomeMilestone` — уходят в `text` (не дробим). Если позже понадобится `fearClosed`-матчинг — вытащим из `text` LLM-проходом.

## 7. Валидация

Общая (`lib/validate/`) + case-специфика:
1. `id` уникальны (69).
2. `text` непустой.
3. Нет остаточного экранирования.
4. `pillar ∈ {PROOF, METHOD, TRUST, HUMAN}` или null.
5. `sourceUrl` — валидный URL или null.
6. Кол-во = 69.
