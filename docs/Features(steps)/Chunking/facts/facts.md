## 2. КРИТИЧНО: два формата карточек в FACTS.md

Файл неоднороден. Парсер обязан понимать оба формата:

### Формат A — карточки F-0001…F-0024
- Заголовок: `\## Карточка`
- Поля с маркером `\- ` (экранированное тире): `\- ID: F-0001`
- Разделитель карточек: `\-\--`
- Значения однострочные.

### Формат B — карточки F-0025…F-0071
- Заголовок: `Карточка:` (с двоеточием, без `##`)
- Поля с маркером `• ` (буллет): `• ID: F-0025`
- Разделитель: `\-\--`
- Значения бывают **многострочными** и **пустыми**.

### Подводные камни (проверил на реальных данных)
1. **Многострочные значения.** В F-0025 «Что произошло:» раскрывается под-буллетами `--- …`:
   ```
   • Что произошло:
   --- Поздравил читателей…
   --- Пожелал «высокого полёта»…
   ```
   Строки `--- …` — это продолжение значения, НЕ новое поле.
2. **Пустые поля.** F-0026: `• Запреты/триггеры:` без значения → `[]`/`null`.
3. **`•` как разделитель внутри значения.** В F-0025 «Теги: TRUST … • HUMAN … • METHOD …» — `•` тут ВНУТРИ строки (разделяет теги), а не маркер поля. Маркер поля — только `• ` **в начале строки**.
4. **Экранирование markdown** по всему файлу: `\##`, `\-`, `\-\--`, `\~`, `«»` и т.д.

---

## 3. Правила парсинга (детерминированные)

1. **Границы карточек:** строка-заголовок `\## Карточка` или `Карточка:`; либо разделитель `\-\--`. (Начинаем новую карточку на заголовке.)
2. **Маркер поля:** `^\s*\\?- ` или `^\s*• ` (в начале строки). Имя поля — до первого `:`.
3. **Известные поля** (белый список): `ID, Период, Сцена, Контекст, Что произошло, Мой вывод, Эмоция/тон, Можно публично, Запреты/триггеры, Теги`. Только они открывают новое поле.
4. **Продолжение значения:** строка без маркера известного поля (в т.ч. `--- …`, `• …` внутри значения, пустые) → добавляется к текущему полю.
5. **Пустое значение** → `null` / `[]`.
6. **Теги:** значение режется по ` • ` (пробел-буллет-пробел) на `string[]`.

---

## 4. Очистка (перед маппингом)

Минимальный детерминированный проход (полный модуль `src/core/cleanup` в репо не развёрнут):
- снять экранирование: `\#`→`#`, `\-`→`-`, `\--`→`—` (или `-` по контексту), `\~`→`~`, `\[`→`[`, `\]`→`]`, `\\_`→`_`;
- схлопнуть 3+ пустых строк, убрать пробелы по краям;
- НЕ трогать смысловые слова, числа, URL.
- `text` кладём уже очищенным.

## 5. Схема данных чанка `fact` (JSON)

Принцип: **не режем сильно** — весь контент карточки в `text` (он же в вектор). Отдельными полями только то, что нужно для фильтрации/поведения.

```jsonc
{
  "id": "F-0001",                 // PK, человекочитаемый
  "type": "fact",
  "text": "Работа официантом… Отработал месяц и получил 4 000 ₽; уволился. Мой вывод: найм с копейками — не мой путь. Эмоция: решимость. Теги: HUMAN, старт. Можно публично: да…", // ВЕСЬ контент → в вектор
  "canPublish": "yes",            // yes | partial | no — влияет на возможность использовать
  "sourcePath": "docs/Facts:Case:Best/FACTS.md",
  "addedAt": "<ISO>"
}
```

### Типы полей
| Поле | Тип | Источник |
|---|---|---|
| `id` | string PK | `ID` |
| `type` | enum | `fact` |
| `text` | string | **вся карточка** (что произошло + вывод + сцена + контекст + эмоция + запреты + теги + можно публично + период), очищенная |
| `canPublish` | enum yes/partial/no | `Можно публично` |
| `sourcePath` | string | путь (один на файл; пригодится для новых файлов) |

## 8. Валидация блока fact

1. `canPublish ∈ {yes, partial, no}`.
2. `id` уникальны (71 + ~25).
3. `text` непустой.
4. Нет остаточного экранирования (`\##`, `\-`, `\~`).
5. Кол-во карточек = 71 (Format A 24 + Format B 47).
6. PRODUCT_FACTS: каждый чанк ссылается на существующий источник.
